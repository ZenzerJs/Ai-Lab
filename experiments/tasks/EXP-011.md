# EXP-011: Policy-Enforced API Gateway & Rate-Limit Billing Engine

Build a high-performance, policy-enforced API gateway with sliding-window rate limiting, cryptographic webhook verification, tiered usage billing, and an accessible policy inspection console.

## Target Architecture (6 Files)
1. `gateway/limiter.py`: Dual-strategy rate limiter (sliding log window and token bucket) with burst controls and per-tenant quotas.
2. `gateway/webhook.py`: Outbound and inbound webhook processor with HMAC SHA-256 signing, timestamp replay protection, and exponential retry dispatch.
3. `gateway/billing.py`: Tiered usage accounting engine (Free, Pro, Enterprise) calculating quota consumption and tiered overage fees.
4. `gateway/router.py`: HTTP request router with extensible middleware pipeline (auth, rate limiting, audit logging, telemetry).
5. `gateway/console.html`: Client-side admin console rendering live policy rules, quota gauges, and webhook delivery logs with full keyboard accessibility.
6. `tests/test_exp011.py`: Test suite verifying rate limiting burst boundaries, constant-time webhook signature verification, and billing tier thresholds.

## Planted Defects & Edge Cases to Fix
- **Rate Limiter Burst Leak**: Sliding window comparison off-by-one error allows an extra request beyond burst limit at window boundary.
- **Webhook Timing Vulnerability**: Signature verification compares hex digests using naive string equality (`==`) susceptible to timing attacks instead of constant-time comparison.
- **Billing Tier Overage Boundary**: Truncation bug in tier calculation overcharges or undercharges usage units sitting exactly on tier threshold borders.

## TSK-025 Evaluation Rubric
- **1. Correctness (0–5)**: All pytest assertions pass (strict burst enforcement, constant-time validation, exact billing).
- **2. Engineering Practices (0–5)**: Standard library only (`hmac`, `hashlib`, `time`, `math`), robust typing, zero linter warnings.
- **3. Maintainability (0–5)**: Functions <=50 LOC, pure deterministic logic, modular separation between router and billing.
- **4. Process Discipline (0–5)**: Confined strictly to 6 manifest files with diff-only edits.
- **5. Design & UX (0–5)**: Accessible admin dashboard (semantic HTML, ARIA labels, responsive table/gauges).
